# Canvas 기능과 검증 범위

## 기본 사용

1. Cheshi 왼쪽 탐색 레일에서 **Canvas**를 연다.
2. EXPLORER 왼쪽 **CANVAS** 헤더의 **+**로 `design-tests` 같은 워크스페이스 안의 폴더를 선택한다.
   문서가 없으면 공통 CANVAS 헤더와 중앙 안내를 표시한다. 헤더의 **New canvas** 아이콘,
   편집기의 File → New 또는 문서 탭의 **+**로 새 문서를 만들고 하단 도구로 프레임·도형·텍스트를 그린다.
3. 오른쪽 레일의 **Pages and layers**에서 페이지와 레이어를 관리한다.
4. 요소를 선택하고 **Properties**에서 Design / Lint 탭을 연다.
5. CANVAS 헤더의 저장 아이콘이나 **⌘S / Ctrl+S**로 저장한다. 처음에는 `example` 같은 이름만 입력한다.
6. 사이드바 파일 목록이나 Explorer의 `.fig` 파일로 다시 연다. 파일 우클릭 → **Rename** 또는 F2로 이름을 바꾼다.
7. 오른쪽 레일의 **Version history**에서 저장 시점과 설명을 확인하고 이전 버전을 복원한다.
   복원은 현재 내용을 보존한 새 버전이며, 이력 저장 경로는 화면에 노출하지 않는다.

원본 Recent/Storage 홈과 별도 검색·Open/New design 영역은 사용하지 않는다.
마지막 문서 탭을 닫으면 중앙 안내로 돌아가며, 문서를 열거나 만들기 전에는 저장 아이콘이 비활성화된다.

CANVAS 파일 목록은 Explorer의 공통 행 스타일과 경로 툴팁을 사용한다. 목록 하단
구분선을 없애고 폴더 제목·들여쓰기 안내선·전체 너비의 선택/호버 배경을 맞췄다.
행 높이는 34px, 글자는 10px, 파일 아이콘은 Explorer와 같은 15px이다.
히스토리의 선택한 버전 미리보기·설명·복원 버튼은 하단 저장 안내 위에 고정하고,
버전 목록은 독립적으로 스크롤한다. 낮은 화면에서는 미리보기 상세 내용만 내부 스크롤된다.

메뉴 줄의 문서 이름은 경로 입력칸과 같은 공통 입력 스타일을 사용한다.
X로 입력을 비우고 다시 입력할 수 있으며, Enter 또는 포커스 이동으로 이름을 적용한다.
Esc는 편집을 취소하고, 빈 이름은 기존 이름으로 되돌린다. 이 입력은 문서 표시 이름을
바꾸며 디스크의 파일 이름은 왼쪽 파일 목록의 Rename으로 변경한다.

File / Edit / View / Object / Text / Arrange 메뉴는 같은 줄의 오른쪽에 정렬한다.
Properties의 Design·Lint 이름은 10px 글자로 유지하고, 앞에 각각 자·연필과 체크 목록
모양의 Lucide 아이콘을 함께 표시한다. 아이콘은 11×11px이며 이름은 툴팁과 접근성
레이블로도 제공한다. 좁은 패널에서도 두 이름을 숨기지 않는다. Lint의 오류·경고 색상과
키보드 탭 전환은 유지한다.

문서 탭은 공통 원형 타이틀 스타일에 Canvas 아이콘을 표시한다.
왼쪽 기본 탐색 레일에서는 Canvas가 첫 항목이다. 메뉴 줄의 Toggle UI 버튼은 제거했다.
오른쪽 레일의 톱니바퀴 아래에는 이력 아이콘이 있으며, 설정 패널에는 **Toolbar**만 제공한다.
도구 모음 우클릭 메뉴와 Cmd/Ctrl+,도 같은 패널을 연다. X·Escape·톱니바퀴 재클릭으로
닫고, 다른 레일 항목을 누르면 해당 패널로 전환한다. 별도의 모달은 열지 않는다.
오른쪽 레일 버튼은 릴레이션 그래프와 같은 공통 스타일로 22×22px, 아이콘은 11×11px다.
편집기 UI 글자는 10px, 눈금 숫자는 9px이며 디자인 안의 텍스트 크기는 바꾸지 않는다.
도구 표시·숨김, 순서·그룹 변경,
기본값 복원은 원본 Toolbar 편집기를 사용한다. 나머지 설정 화면과 원본 AI 탭,
AI 초기 설정 창, Cmd/Ctrl+J의 AI 진입점은 통합 빌드에서 제거했다.

Code 탭과 수동 코드 편집·출력 화면도 통합 빌드에서 제외했다. Design JSX,
HTML/CSS 입력과 React·Vue 출력은 해당 패널에서 제공하지 않는다. 원본 편집 API와
파일 내보내기 기능은 유지하며, Cheshi 에이전트 도구 연결은 별도 작업이다.

화면의 빨간색/노란색 숫자 표시는 원본 디자인 검사 결과다. 개발자 콘솔 오류 표시가
아니다. View 메뉴의 디자인 검사 표시 옵션으로 화면 표시를 조절할 수 있다.

## 제공하는 편집 기능

다음 기능은 핀으로 고정한 원본 구성요소와 명령을 연결한다. React에서 기능을
별도로 흉내 내는 방식이 아니다. 아래의 **제공 기능**과 뒤의 **실행한 검사**는 구별한다.
모든 옵션 조합을 하나씩 검증한 목록은 아니다.

| 영역 | 제공 기능 | 진입점 |
| --- | --- | --- |
| 문서 | 새 탭, 열기, 저장, 다른 이름으로 저장, 미저장 변경 확인, 버전 이력·복원 | CANVAS 사이드바, File 메뉴, 탭 |
| 페이지·레이어 | 페이지 추가·이름 변경·정렬, 계층 펼치기, 선택, 숨김·잠금·순서 변경 | Pages and layers |
| Assets | 컴포넌트 목록, 인스턴스, 라이브러리 관련 원본 화면 | 레이어 패널의 Assets |
| 기본 도구 | 선택, 프레임/섹션, 사각형·타원 등 도형, 펜, 텍스트, 이동, 댓글 | 하단 원본 도구 모음 |
| 편집 | 실행 취소/다시 실행, 복제·삭제, 그룹/그룹 해제, 선택 명령 | Edit / Object 메뉴, 단축키 |
| 위치·크기 | X/Y, W/H, 회전, 반전, 정렬, 분배, 프레임 프리셋 | Design / Arrange 메뉴 |
| Auto layout | 가로·세로·그리드, 간격·패딩, 정렬, 크기 방식, 클리핑 | Design의 Auto layout |
| 외형 | 채우기, 그라디언트, 선, 효과, 불투명도, 혼합 모드, 모서리 | Design |
| 텍스트 | 글꼴, 크기·굵기, 줄/문자 간격, 정렬, 인라인 편집 | Text 메뉴, Design |
| 벡터 | 펜과 점 편집, 불리언 연산, 경로 관련 원본 명령 | 도구 모음 / Object |
| 컴포넌트 | 생성, 인스턴스, 오버라이드, 원본의 변형·속성 컨트롤 | Object / Assets / Design |
| 변수 | 원본 변수 컬렉션과 값 편집 UI | 메뉴의 Variables |
| 상태·댓글 | 원본 상태 대화상자, 댓글 도구·패널 | 메뉴와 도구 모음 |
| 보기 | 확대/축소, Fit, 눈금자, 가이드, 스냅, 분할 보기 | View, 확대율 메뉴 |
| 프리뷰 | 프레임 미리보기와 종료 | 오른쪽 Preview |
| 내보내기 | PNG/SVG/PPTX/.fig 등 원본 파일 내보내기 | File → Export Selection |
| 디자인 검사 | 원본 규칙의 오류·경고 목록과 캔버스 표시 | Check / View |
| 설정 | Toolbar 표시·숨김, 순서·그룹 변경, 기본값 복원 | 오른쪽 레일 톱니바퀴 / Toolbar 우클릭 / Cmd/Ctrl+, |

Auto layout은 디자인 안의 카드·버튼을 일정한 간격으로 정렬하는 기능이다.
Cheshi의 패널을 다른 위치로 옮겨야 한다는 뜻이 아니다.

## 외부 연결

| 항목 | 이번 통합 상태 | 조건·검증 한계 |
| --- | --- | --- |
| 로컬 디자인 편집·저장 | 연결 | 별도 서버 없이 실행하며 임시 `.fig`로 개발앱 검사 |
| 원본 AI 탭·공급자 설정 | 제거 | Cheshi 자체 AI를 사용한다. Canvas 조작 도구 연결은 별도 작업 |
| Share / 실시간 협업 | 개인용 구성에서 제거 | 사용자 아바타·Share·공유방 참여·음성 통화를 제거하고 P2P 연결을 차단 |
| 외부 저장소·라이브러리 | 원본 문서·라이브러리 UI 포함, 설정 화면은 제거 | 새 저장소 연결 설정을 제공하지 않음. 실제 업로드/게시하지 않음 |
| OpenPencil Cloud 계정·버전 기록 | 빌드에서 비활성화 | 별도 Cloud 서비스를 제공하는 통합은 포함하지 않음 |
| Tauri 네이티브 서버·MCP | 실행하지 않음 | Cheshi의 로컬 파일 IPC로 교체. 에이전트 도구 연결은 별도 작업 |
| 온라인 글꼴·아이콘 검색·투어 | 원본 진입점 포함 | 외부 자원이 필요한 동작은 연결 환경에 따라 달라짐 |

따라서 외부 공급자를 포함한 모든 기능의 실서비스 테스트가 끝났다는 의미로
“완료”를 사용하지 않는다. 원본 기능을 가져오는 것과 Cheshi 에이전트가 해당 기능을
도구로 호출하는 것은 별도 연결 작업이다.

## 실행한 검사 — 2026-10-19

### 격리된 Electron

`desktop/test/original-canvas-runtime.test.ts`는 실제 원본 빌드, 워커와 CanvasKit을
임시 프로필에서 실행한다. 외부 HTTP/WS를 차단하고 콘솔 오류·경고가 없음을 검사한다.

- 도형 생성·속성 변경, 실행 취소/다시 실행.
- 그룹/그룹 해제, 자동 배치, 컴포넌트와 인스턴스.
- 한글 텍스트, 복제·삭제/복원, 숨김·잠금.
- 두 페이지 사이 이동, 프리뷰 진입/종료.
- 원본 저장 어댑터가 전달한 `.fig` 바이트를 다시 열어 구조·한글·레이어 상태 확인.
- 원본 메뉴·속성 패널·캔버스 크기 확인.
- PNG/SVG/PPTX 내보내기의 생성 파일 형식 확인.
- 패널 내부에서 Escape로 닫을 때 버튼으로 포커스 복귀.
- 편집 화면의 공유 UI와 시작 화면의 공유방 참여가 없으며, 공동 편집 연결 요청을 거부.
- 문서 이름의 X 지우기, 빈 이름 복원, IME 조합 중 Enter 보류, Enter 확정과 Esc 취소.
- Canvas 탭 아이콘과 Toolbar 전용 설정, AI 탭·단축키 제거 확인.
- Toolbar 도구 숨김·설정 재열기 후 유지, 그룹 안의 순서 변경과 기본값 복원.
- Toolbar 설정의 오른쪽 패널 배치, 모달 미생성, 설정 단축키와 Escape 포커스 복귀.
- 요소 선택 후 속성 탭이 Design / Lint만 표시되고 Code 패널이 마운트되지 않음.
  Design / Lint 전환과 Escape 닫기, 기존 편집·저장·내보내기 회귀 검사.

네이티브 Canvas 검사에서는 디스크 읽기/저장, 외부 변경 충돌, 경로 경계,
워크스페이스별 마지막 문서, preload 전달과 패키징 허용 목록을 확인한다.
캔버스 라이브러리 검사는 버전 중복 제거, 재시작 후 조회, 외부 변경 보존,
충돌 거부, 저장 저널 복구, 손상된 이력 보호와 삭제된 파일 복원을 포함한다.
사이드바 검사는 복원 확인과 미저장 상태 보호, 1px 대체 썸네일 제외를 확인한다.
선택 폴더의 프로세스 재시작 후 유지, 폴더 밖 경로 거부, 이름 변경 시 이력 보존,
동일 이름·외부 변경 충돌과 동시 이름 변경도 검사한다. 실제 편집기 회귀 검사에는
미저장 문서의 이름 변경과 빈 저장 파일을 열 때 재사용 탭을 유지하는 경우를 포함한다.
이력의 저장 위치와 에이전트 체크포인트 연결 범위는 [저장 구조](canvas.md#워크스페이스-파일과-버전-이력)를 참고한다.

### 개발앱의 실제 입력

Canvas 폴더·이력 변경 후에는 1362×861 CSS 픽셀의 개발앱에서 별도 iframe 입력
시나리오로 폴더 선택·취소, 새 파일 저장, 미저장 상태의 이름 변경, 저장 아이콘과 ⌘S,
이전 버전 복원, 설정/이력 패널 전환을 확인했다. 공통 너비 전환과 가로 넘침 없음을
측정하고 스크린샷을 확인했다. 앱을 완전히 종료·재실행한 뒤 선택 폴더, 마지막 파일과
이력 4개가 유지되는 것을 확인했다. 첫 재실행 검사에서 빈 파일의 재사용 탭이 닫히는
문제를 발견해 수정한 뒤 같은 시나리오를 통과했다. 검사 중 런타임 예외는 0건이었다.
테스트용 `.canvas-review-20261019` 폴더의 파일과 이력을 정리하고 원래 폴더·문서·탐색
화면·사이드바 상태를 복원했다. 입력 자동화의 폴더 이동, 로딩 대기와 복원 조건을
보완한 과정은 제품 결함과 구별한다.

현재 체크아웃의 **Cheshi Development**에서 Inspector 연결과 실제 Electron
마우스/키보드 입력을 사용했다. 창은 1280×750이며 기존 저장 문서로 되돌렸다.
iframe 입력·드래그는 공유 Inspector 전송을 쓰는 별도 시나리오로 검사했다.

- 오른쪽 레이어 패널 열기/닫기, 캔버스 크기·이동·확대율 유지.
- 새 탭, 페이지 추가, `R` 단축키와 마우스 드래그로 사각형 생성.
- 선택 요소의 속성, Code / Check 탭 전환(당시 구성; 이후 Code 탭 제거).
- 속성 숫자 입력, Shift+A 자동 배치.
- File / Edit / View / Object / Text / Arrange 메뉴, 설정 창과 Assets 탭.
- Escape로 패널 닫기와 레일 버튼 포커스 복귀.
- 경로 입력 후 저장, 탭을 닫고 디스크에서 다시 열어 두 페이지와 도형 복원.
- 해당 시나리오의 콘솔 오류·경고 0건.
- 실제 창 스크린샷으로 메뉴·점무늬 배경·눈금자·도구 모음을 확인.
- 문서 이름 입력칸은 별도 임시 탭에서 실제 입력으로 X·Tab·Enter·Esc를 검사했다.
  경로 입력칸과 높이 32px, 배경색, 둥근 모서리, 글꼴 크기가 일치하며 메뉴 줄은 42px다.
  로고 제거와 입력칸 배치를 스크린샷으로 확인하고 원래 문서·페이지·선택·확대율·위치를 복원했다.
- 문서 탭 아이콘은 공통 타이틀과 같은 원형 22px·아이콘 11px로 확인했다.
  Toolbar 전용 설정에서 실제 클릭으로 표시 여부를 변경하고 재열기 후 유지를 확인했으며,
  방향키로 순서를 바꾼 뒤 원래 설정으로 복원했다. 당시 Design / Code / Check 전환과
  Cmd+J의 AI 미진입, Escape 닫기를 확인했고 해당 검사 중 콘솔 오류·경고는 0건이었다.

검사 파일은 `design-tests/.canvas-original-editor-check.fig`와
`design-tests/.canvas-original-editor-reopen-check.fig`다. 테스트용이며 제품 데이터가 아니다.
기존 `design-tests/zenith-dashboard.fig`의 내용을 덮어쓰지 않았다.

### Code 화면 제거 확인

Code 제거 후 최종 번들을 별도 임시 프로필의 Electron에서 확인했다. 실제 마우스로
Design / Lint 전환, 선택 유지, Escape 닫기와 레일 버튼 포커스 복귀를 검사했다.
Code 입력·출력 패널이 없음을 DOM과 스크린샷으로 확인했고, 이 검사에서 콘솔
오류·경고와 외부 요청은 0건이었다. 초기 검사 스크립트의 앱 시작 대기와 패널 슬라이드
완료 대기를 바로잡은 후 통과했다.

당시 개발앱에는 미저장 변경이 있어 새로고침하지 않고 별도 프로필로 확인했다.

### 레일·글자 크기 변경 확인

개발앱을 현재 체크아웃으로 실행하고 실제 마우스로 Canvas 진입, 오른쪽 설정 열기,
Escape 닫기와 버튼 포커스 복귀, Pages and layers / Properties 전환을 확인했다.
버튼 22×22px·아이콘 11×11px, 메뉴·속성·설정의 10px/9px 글자 크기를 측정하고
스크린샷을 확인했다. 패널 전환 전후 문서 위치·확대율과 문서 변경 여부를 비교하고,
검사 후 패널·선택·문서 상태와 원래 탐색 화면을 복원했다.
초기 검사의 문서 로딩 완료 대기와 스크린샷의 애니메이션 대기를 보완했다.
별도 Electron 회귀 검사에서는 설정의 도구 숨김·순서·복원, 저장·재열기 후 문서의
24px 텍스트 유지와 내보내기를 검사했다. 이 검사들의 콘솔 오류·경고는 0건이었다.

원본 기능 전체의 모든 조합, 다양한 화면 크기, 외부 서비스까지 검증했다고 주장하지 않는다.

### 헤더 여백과 설정 사이드 패널 확인

워크스페이스 헤더의 추가 버튼은 실제 개발앱에서 상하좌우 여백을 각각 8px로 측정했다.
버튼 22px와 아래 구분선 1px을 포함한 헤더 높이는 39px이며, 아래 워크스페이스가
헤더 경계에 맞춰 배치되는 것을 확인했다. 헤더 관련 3개 UI 검사를 통과했다.

Canvas에서는 실제 클릭과 키보드 입력으로 설정 관련 15개 UI 검사를 통과했다.
톱니바퀴·우클릭 메뉴·Cmd+, 진입, X·Escape·톱니바퀴로 닫기, Properties로 전환,
도구 표시 변경과 재열기 후 유지, 10px 글자 크기와 가로 넘침 없음을 확인했다.
스크린샷에서 오른쪽 패널 배치를 확인했고 문서 위치·확대율·선택·기존 설정을 복원했다.
이 검사 중 콘솔 오류·경고와 런타임 예외는 0건이었다.

워크스페이스 탭·레이아웃 자동 검사 9개와 격리된 Electron 회귀 검사 2개를 통과했다.
렌더러 빌드, 렌더러·데스크톱·데스크톱 테스트 타입 검사도 통과했다.

### 메뉴 오른쪽 정렬과 아이콘 탭 확인

개발앱에서 메뉴 오른쪽 정렬, 메뉴 6개의 실제 열기·Escape 닫기, 헤더 42px와
글자 10px 유지, 두 탭의 11px 아이콘과 접근성 이름, 툴팁, 클릭·방향키 전환을
검사했다. 총 15개 확인 항목이 통과했고 스크린샷으로 배치를 확인했다.
원래 문서·선택·위치·확대율·탭·패널과 설정을 복원했다.

검사 중 새 콘솔 오류·경고와 런타임 예외는 0건이었다. 디버거 연결 때 재전송된
이전 검사 스크립트의 예외 1건은 이번 조작 결과와 별도로 기록했다.
최종 렌더러 빌드, 렌더러·데스크톱 타입 검사와 격리된 Electron 회귀 검사 2개를 통과했다.

아이콘 옆 Design·Lint 이름을 복원한 뒤에는 임시 프로필의 900px·1200px 화면에서
글자 10px·아이콘 11px과 두 탭의 실제 클릭 전환을 확인하고 스크린샷을 검토했다.
이 검사 중 콘솔 오류·경고와 런타임 예외는 0건이었다. 빌드·타입 검사와 기존 Electron
회귀 검사 2개도 통과했다. 개발앱에는 탭 3개가 열려 있어 새로고침하지 않았다.

### SESSION과 공통 슬라이드 동작

Canvas의 레이어·속성·설정 패널은 SESSION이 사용하는
`desktop/frontend/src/shared/ui/SlidingSidePanel.module.css`와 패널 테두리 스타일을
직접 가져온다. 별도 이동·투명도 효과를 제거했고, 닫을 때 마지막 내용을 유지하면서
`inert`와 `aria-hidden`으로 상호작용을 차단한다.

최종 빌드의 임시 Electron 프로필에서 실제 마우스·키보드 입력으로 19개 확인 항목을
통과했다. 세 패널의 열기·닫기 중간 프레임, 빠른 재클릭, Escape 포커스 복귀,
문서 이동·확대율 유지와 동작 줄이기 설정을 확인했다. 900px·1200px 화면을 사용했고
스크린샷에서 패널 배치와 Design·Lint 이름을 검토했다. 오류·경고·런타임 예외는 0건이다.
기존 Electron 회귀 검사 2개, 렌더러 빌드와 렌더러·데스크톱 테스트 타입 검사도 통과했다.

이때 현재 체크아웃의 개발앱은 실행 중이지 않아 실행 중인 사용자 화면과의 비교 검사는
하지 않았다. 900px 다크 화면에서도 기존 패널 너비는 320px로 측정됐다. 좁은 화면용
220px 규칙은 다크 테마 선택자의 우선순위에 가려져 있으며, 이번 동작 수정에는 포함하지 않았다.

### 공통 Canvas 시작 화면

Recent/Storage 홈을 공통 CANVAS 헤더와 중앙 안내로 교체했다. 개발앱의 실제 클릭으로
새 문서 생성, 문서 탭의 +, 마지막 탭 닫기, 빈 화면의 저장 비활성화, 사이드바에서 파일
열기를 확인했다. 헤더·안내 글자 10px과 아이콘 11px을 측정하고 스크린샷의 배치를 검토했다.
원래 문서·선택·확대율·이동 위치·패널·사이드바 상태를 복원했다.

공통 Inspector 도구에 Canvas iframe 전용 입력 시나리오를 연결해 8개 항목을 확인했다.
공식 verification runner의 호스트 화면 검사가 아닌 별도 자식 WebContents 입력 검사다.
검사 중 새 런타임 예외는 0건이며, 디버거 연결 시 재전송된 이전 예외 1건은 별도로 기록했다.
사용자가 제공한 변경 전 화면을 기준으로 현재 동작을 확인했으며 동일 입력의 전후 비교는 하지 않았다.

사이드바 회귀 검사 2개, 격리 Electron 회귀 검사 2개, 렌더러·데스크톱 테스트 타입 검사와
렌더러 빌드를 통과했다. 첫 Electron 실행에서는 긴 편집 검사 뒤 탭 닫기를 반복하면서
WebGL 컨텍스트 누적 경고가 발생했다. 시작 화면 검사를 새 렌더러 문서에서 실행하도록
분리한 뒤 오류·경고가 없는 것을 확인했다. 장시간 반복 편집의 그래픽 자원 관리는 별도 검증 대상이다.

### 파일 목록 통일과 히스토리 하단 고정

개발앱에서 목록 하단 보더 제거, 전체 너비와 34px 행 높이, 10px 글자·15px 파일
아이콘, 전체 경로 툴팁, 우클릭 Rename의 입력·취소를 확인했다. 기존 문서 탭을
보존하기 위해 히스토리는 같은 최신 번들의 임시 iframe에 버전 60개를 제공해 검사했다.
일반 높이(최대 700px)와 400px 높이에서 실제 마우스로 목록을 스크롤하고,
미리보기 위치 고정과 복원 버튼의 접근성, 복원 확인창 취소를 확인했다.
화면 스크린샷 3개를 열어 배치를 검토했다. 실제 파일 이름 변경이나 이력 복원은
개발앱에서 수행하지 않았으며, 해당 콜백과 확인 흐름은 자동 회귀 검사로 검증했다.

공통 Inspector 도구의 자식 WebContents 입력 시나리오에서 8개 항목을 통과했다.
검사 중 새 런타임 예외는 0건이고 연결 시 재전송된 이전 예외 2건은 별도 기록했다.
초기 툴팁 검사는 다른 컨트롤의 툴팁을 선택해 실패했으며, 행의 aria-describedby에
연결된 툴팁으로 선택자를 수정한 뒤 통과했다. 동일 입력의 변경 전·후 비교는 하지 않았다.
임시 iframe을 제거하고 원래 문서·탭 수·선택·확대율·이동 위치·사이드바 상태를 확인했다.
사이드바 회귀 검사 2개와 Electron 회귀 검사 2개, 렌더러·데스크톱 테스트 타입 검사,
렌더러 빌드도 통과했다. 열려 있던 기존 편집기 iframe은 강제로 다시 로드하지 않았다.
