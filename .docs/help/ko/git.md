# Git으로 기록하고 공유하기

Commit은 선택한 변경을 Git 이력에 남기고, Push는 커밋을 연결된 원격 저장소로 보냅니다.

## 언제 쓰나요

완료한 작업을 의미 있는 단위로 기록하거나 다른 사람과 공유할 때 사용합니다. Git 저장소가 있는 프로젝트가 필요하며, 푸시하려면 원격 저장소와 접근 권한도 필요합니다.

## 어떻게 하나요

1. 에디터에서 변경한 파일을 저장한 뒤 사이드바의 **Github** 화면을 엽니다.
2. **Local changes**에서 파일을 선택해 추가·삭제된 내용을 확인합니다.
3. **UNSTAGED** 목록의 체크박스로 커밋할 파일을 선택해 **STAGED**로 옮깁니다. STAGED는 이번 커밋에 포함할 변경입니다.
4. **Commit message**에 무엇을 바꿨는지 적고 **Commit**을 누릅니다.
5. 원격에 공유할 때는 **Pull requests** 화면에서 현재 브랜치를 확인합니다. **Push 브랜치명** 버튼이 표시되면 눌러 해당 브랜치의 커밋을 보냅니다.

## 결과는 무엇인가요

커밋하면 선택한 변경이 로컬 Git 이력에 남습니다. 푸시가 성공하면 원격 저장소에도 커밋이 반영됩니다. 저장, 커밋, 푸시는 각각 별도 작업입니다.

Pull requests의 Push 버튼은 브랜치와 원격 상태에 따라 표시됩니다. 버튼이 없다고 모든 변경이 공유된 것은 아닙니다. 새로 만든 프로젝트에는 원격 저장소가 자동으로 연결되지 않으므로, 원격을 준비하고 연결해야 푸시할 수 있습니다.

Local history는 파일 복구용 자동 기록이고 Git 커밋은 선택한 작업의 명시적인 기록입니다. 파일을 저장하거나 로컬 기록을 복원하는 것만으로 Git 커밋이 생기지 않습니다.
