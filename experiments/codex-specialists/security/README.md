# Codex bubblewrap seccomp profile

`codex-bwrap.json` is generated by `profile.ts`. Do not edit the generated file.
The unmodified Moby baseline and its license are vendored under `vendor/`.

- Upstream: <https://github.com/moby/profiles>
- Commit: `2ceae35d351c156cb5a8efc0fdc4a08cf94569d8`
- Source: `seccomp/default.json`
- SHA-256: `6416b47770785a41ac59073cdc77d9fe98517df2799dc83ef207e622de3053f6`

Run from the experiment directory:

```sh
bun security/profile.ts
bun security/profile.ts --check
docker compose config --quiet
```

The original allowlist, default denial, capability conditions, socket-family
restrictions, and `clone3` fallback are preserved. Additional rules let bwrap
create a user namespace and mount its inner filesystem. These rules do not
grant capabilities in the container's original user namespace. Kernel ownership
and capability checks still apply to mount operations.

Keep `cap_drop: [ALL]`, `no-new-privileges`, the non-root user, read-only root,
and read-only source mount together with this profile. The profile broadens the
kernel operations available inside the container; it is scoped to this local
experiment and requires revalidation when the runtime or baseline changes.

On OrbStack / Docker 29.4.0 arm64 / Codex 0.159.3, removing each added syscall
individually prevented sandbox startup:

| Removed exception | Observed bwrap failure |
| --- | --- |
| `clone` | No permissions to create a new namespace |
| `unshare` | unshare user ns: Operation not permitted |
| `mount` | Failed to make / slave: Operation not permitted |
| `umount2` | unmount old root: Operation not permitted |
| `pivot_root` | pivot_root: Operation not permitted |

These removal checks used disposable containers without network or host/auth
volumes. Keep the final profile's generated content in sync with `profile.ts`.
